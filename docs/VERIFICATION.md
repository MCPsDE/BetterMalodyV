# 验证记录

## 1.0.2 大曲库阻塞与灰色标签

确认旧状态谓词在原生 RefreshDisplayList 的显示列表写锁内，对每首未加载歌曲执行 ScanFiles；该调用包含递归目录遍历、数据库读取、谱面解析及哈希，构成与曲库规模相关的主线程长时间阻塞。本次没有把卡死归因为谱面上限，也没有改动其他插件或真实游戏进程。

状态谓词改为已加载歌曲的内存状态或未加载歌曲的不可变索引查询。后台只在临时数据库副本上读取元数据，扫描与解析谱面文件的调用不再出现在歌曲筛选路径。

- 原生隔离宿主读取正式曲库数据库的副本：24,926 条谱面记录，后台建立索引约 0.2–0.4 秒；读取到的真实歌曲路径抽样 1,000 条，124 条可匹配该索引中的 Stable/Beta，验证真实路径关联。
- 实际原生 RefreshDisplayList、实际写锁和原谓词补丁：20,000 首尚未加载的人工歌曲，正确筛出 Stable；每次约 0.05–0.12 秒，ScanFiles 计数为 0。证据记录每次实际计时，而非界面宣称。
- 托管索引测试：200,000 条谱面元数据聚合与 200,000 次查询；覆盖 protobuf 默认 Alpha、未知状态、损坏数据、嵌套路径、Windows 路径规范化和同谱面模式/状态组合。
- 原生测试逐项比较 18 个谱面格式的缓存模式映射与游戏自身 getter，同时校验 protobuf 字段编号。
- 1280×720、1920×1080 的真实 SearchAdv 预制体捕获；三个标签使用半透明灰色，保留输入区域、完整文字、鼠标和键盘勾选。压力测试与 UI 捕获分阶段执行，等待入场动画重新稳定；捕获仍需通过视野边界断言。

最终两种分辨率各通过 80 项原生检查，20,000 首压力歌曲的原生刷新耗时分别为 85/86 ms。复核结论 ship，无待修复项，范围限本次灰色标签与阻塞修复。

证据为 `.impeccable/review/search-native-*.png/.json`。测试只读取正式数据库并复制到 artifacts 宿主，压力歌曲为人工数据；没有安装到或结束用户的正式游戏。计时受硬件和曲库结构影响，不代表所有曲库的速度保证。完整真实联机流程、物理显示器 DPI 未实测。

## 1.0.1 搜索修复

1.0.0 的人工搭建搜索控件样例不能验证真实预制体布局，用户报告只显示原有三个筛选器。本次改用当前游戏 FrontLayerManager.prefabs 中实际 SearchAdv，原生控制器自动发现面板并挂载，测试刻意不调用 Show；原 Show 在实际 interop 标注 CallerCount(0)，不能作为唯一挂载入口。

在隔离 IL2CPP 宿主的 1280×720、1920×1080 两种分辨率下，各 55 项检查通过，包括实际面板发现、输入框内边界、完整单行标签、至少 200 单位文字输入宽度、重复挂载、鼠标事件勾选、键盘提交切换、长关键词输入及原有全部状态过滤检查。截图等待面板入场动画完成，并断言所有控件处于捕获视野内。证据为 `.impeccable/review/search-native-<宽>x<高>.png/.json`。

两种分辨率均使用 CanvasScaler 做游戏 UI 合成适配，不代表物理显示器 DPI 测试。谱面数据仍为人工记录；联机入口与大厅共用这个预制体，但未进行真实账号联机对局。没有修改或安装到用户的正式游戏目录。
